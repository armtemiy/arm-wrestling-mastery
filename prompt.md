Вот подробный комплексный аудит вашего лендинга, основанный на анализе предоставленной кодовой базы (React, Vite, Tailwind, TypeScript, Framer Motion).

---

## 📋 Общее резюме состояния проекта

Проект использует современный стек (Vite, React, TypeScript, Tailwind CSS, shadcn/ui). Архитектура директорий выстроена логично. Однако есть проблемы с производительностью (отсутствие ленивой загрузки тяжелых компонентов), SEO-оптимизацией базового HTML, доступностью (a11y) и хардкодом данных внутри UI-компонентов.

## 🗂 Приоритизация задач (ТЗ на исправления)

**Логика приоритизации:**

1. **Critical:** То, что влияет на индексацию (SEO) и конверсию (неработающие/медленные элементы).
2. **High:** Производительность (Core Web Vitals) и критический UX.
3. **Medium:** Поддерживаемость кода, доступность (a11y), рефакторинг.
4. **Low:** Микро-улучшения.

### 🔴 Задача 1: Базовая SEO-оптимизация и Meta-теги (Critical)

* **Описание проблемы:** Лендинг не будет красиво отображаться при шеринге в соцсетях (Telegram, VK, Twitter), поисковики не получат достаточно семантики.
* **Ожидаемое поведение:** Присутствуют заполненные теги title, description, og:title, og:description, og:image, twitter:card. Добавлен `rel="preconnect"` для внешних шрифтов/ресурсов.
* **Шаги исправления:**
1. Отредактировать `<head>` в `index.html`.
2. Добавить `og:image` (размер 1200x630) в папку `public/`.
3. Добавить `theme-color`.


* **Затрагиваемые файлы:** `index.html`, `public/`.
* **Оценка сложности:** 1 story point.
* **Definition of Done (DoD):**
* Код проходит проверку валидатора W3C.
* Теги отображаются при парсинге через Telegram Webpage Bot.
* Прохождение линтеров без ошибок.



### 🟠 Задача 2: Оптимизация бандла (Code Splitting) (High)

* **Описание проблемы:** `Index.tsx` импортирует все секции статически, что ведет к огромному первому бандлу.
* **Ожидаемое поведение:** Секции, находящиеся ниже сгиба (Below the fold) — `FAQSection`, `ProgramSection`, `Footer` — загружаются лениво.
* **Шаги исправления:**
1. Использовать `React.lazy()` и `<Suspense>` для импорта секций в `Index.tsx`.
2. Настроить фоллбэки (скелетоны или минимальные заглушки) для `<Suspense>`.


* **Затрагиваемые файлы:** `src/pages/Index.tsx`.
* **Риски:** Возможен Cumulative Layout Shift (CLS), если фоллбэки не совпадают по высоте с контентом. Обязательно задать минимальную высоту контейнерам.
* **Оценка сложности:** 3 story points.
* **Definition of Done (DoD):**
* Размер `main.js` в network вкладке уменьшен на 30-40%.
* Отсутствие регрессий визуального отображения (CLS = 0).
* Lighthouse Performance Score > 90.



### 🟠 Задача 3: Оптимизация компонента Particles (High)

* **Описание проблемы:** Анимация на canvas потребляет ресурсы, даже если пользователь проскроллил страницу вниз.
* **Ожидаемое поведение:** Анимация ставится на паузу (отменяется `requestAnimationFrame`), когда компонент не виден на экране.
* **Шаги исправления:**
1. Использовать `IntersectionObserver` (например, хук `useInView` из `framer-motion`).
2. Оборачивать логику отрисовки кадра в проверку `if (isInView) { render(); requestAnimationFrame(...) }`.


* **Затрагиваемые файлы:** `src/components/landing/Particles.tsx`.
* **Оценка сложности:** 2 story points.
* **Definition of Done (DoD):**
* Профилировщик Chrome (Performance tab) показывает падение CPU usage до ~0%, когда секция с Particles вне viewport.
* Кроссбраузерность: работает в Safari, Chrome, Firefox.



### 🟡 Задача 4: Разделение данных и UI (Medium)

* **Описание проблемы:** Тексты, списки модулей, вопросы FAQ жестко зашиты в JSX. Это паттерн "God Object" на уровне компонента.
* **Ожидаемое поведение:** Данные вынесены в отдельные файлы конфигурации.
* **Шаги исправления:**
1. Создать директорию `src/data/`.
2. Создать файлы `faq.ts`, `program.ts`, `features.ts`.
3. Экспортировать массивы объектов и использовать `.map()` в компонентах.


* **Затрагиваемые файлы:** `FAQSection.tsx`, `ProgramSection.tsx`, `src/data/*`.
* **Оценка сложности:** 2 story points.
* **Definition of Done (DoD):**
* В JSX нет хардкод-массивов с текстами (кроме заголовков секций).
* Типизация данных строго описана через интерфейсы (например, `interface FAQItem { question: string; answer: string; }`).



### 🟡 Задача 5: Улучшение Accessibility (a11y) формы (Medium)

* **Описание проблемы:** Форма в `TerminalContactForm` может быть недоступна для скринридеров, если используются только placeholder.
* **Ожидаемое поведение:** Все интерактивные элементы имеют связанные лейблы.
* **Шаги исправления:**
1. Добавить `id` каждому `<input>` и `<textarea>`.
2. Добавить `aria-label` или визуально скрытый (класс `sr-only`) `<label htmlFor="id">`.
3. Добавить `aria-invalid` для отображения стейтов ошибок.


* **Затрагиваемые файлы:** `src/components/landing/TerminalContactForm.tsx`.
* **Оценка сложности:** 1 story point.
* **Definition of Done (DoD):**
* Проверка Lighthouse (Accessibility) > 95.
* 0 ошибок при проверке плагином axe-core.

## 🏗 Рекомендации по улучшению архитектуры

1. **Изоляция API-слоя:**
Сейчас обращение к Supabase происходит прямо в компоненте формы `TerminalContactForm.tsx`.
*Решение:* Вынести логику в кастомный хук `src/hooks/useSubmitLead.ts` или в отдельный сервис `src/services/api.ts`. Это сделает форму "глупой" (dumb component), её будет легче тестировать.
2. **Консолидация стилей:**
У вас есть `tokens.css`, `typography.css` и мощный конфиг в `tailwind.config.ts`.
*Решение:* Перенести все CSS-переменные из `tokens.css` в секцию `theme.extend.colors` Tailwind-конфига (если это возможно) или жестко привязать Tailwind к CSS-переменным (`colors: { primary: 'var(--primary)' }`), чтобы оставить один источник истины для дизайн-токенов.
3. **Управление состоянием UI:**
Убедитесь, что глобальные состояния (например, открытие мобильного меню) не вызывают лишних ререндеров тяжелых секций (разделите провайдеры контекста).

## 🚀 Рекомендации по оптимизации производительности

1. **Динамический импорт иконок:** Если используется библиотека иконок (lucide-react, heroicons), убедитесь, что настроен tree-shaking, либо импортируйте их строго: `import { Menu } from 'lucide-react'`.
2. **Настройка шрифтов:**
Используйте `font-display: swap;` во всех `@font-face` декларациях (в `typography.css`), чтобы избежать невидимого текста (FOIT) во время загрузки шрифта.
3. **Prefetching:**
Для критичных ресурсов (например, картинки в Hero секции) добавьте `<link rel="preload" as="image" href="...">` в `head`.

## ⚡ Quick Wins (Быстрые улучшения за 5 минут)

1. **Ленивая загрузка изображений:**
Пройдитесь по всем тегам `<img>` (или компонентам `OptimizedImage`) и убедитесь, что для картинок ниже первого экрана стоит `loading="lazy" decoding="async"`.
2. **Удаление неиспользуемого кода:**
Проверьте `.temp` файлы в папке `supabase/` и убедитесь, что они добавлены в `.gitignore`.
3. **Защита кнопок:**
В `TerminalContactForm` добавьте `disabled={isSubmitting}` на кнопку отправки, чтобы предотвратить двойной клик и спам запросами в БД.
